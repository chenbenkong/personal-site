## 好的提交信息长什么样

不要写 `fix bug`、`update`。试着写清楚**为什么**：

```text
feat: 新增博客 RSS 订阅
fix: 修复移动端导航栏溢出问题
```

## 一个简单的工作流

1. 从 `main` 切出功能分支：`git checkout -b feat/xxx`
2. 小步提交，信息清晰。
3. 推到远程，开 PR，描述做了什么、为什么。

## 为什么值得

哪怕只是个人项目，规范的提交历史也是你**技术素养**的简历。
招聘的人真的会看你的 GitHub。
